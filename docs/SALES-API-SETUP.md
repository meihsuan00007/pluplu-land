# 銷量統計 API 部署指南（Google Apps Script）

讓官網「熱銷排行」排序能拿到各商品的累計銷量，**而且銷售紀錄試算表維持 100% 私密**：
試算表不開任何共用、不開「知道連結可檢視」，對外只有一支你自己帳號裡的小程式，
它只會吐出「商品名稱：累計售出數量」的統計數字，其他欄位（客人資料、金額）完全不經手。

> 全部步驟只要做一次，之後試算表照常記錄，官網每次載入會自動抓最新統計（最多延遲 5 分鐘）。

## 第一步：把腳本放進你的試算表

1. 用你自己的 Google 帳號打開「銷售紀錄」試算表。
2. 上方選單點 **擴充功能 → Apps Script**，會開一個新分頁（這個程式就「住」在這份試算表裡，天生只有你能動）。
3. 把編輯器裡原本的內容全部刪掉，貼上專案裡 `scripts/gas-sales-api.gs` 的完整內容。
4. 看一下最上面的設定區，需要時調整：
   - **`SPREADSHEET_ID`（必填）**：試算表網址中 `/d/` 與 `/edit` 之間那一長串。
     （一定要填：網頁方式被呼叫時腳本不一定「站在試算表裡面」，
     不填會出現「指定的權限不足，無法呼叫 SpreadsheetApp」的錯誤。）
   - `SHEET_NAME`：你的銷售紀錄放在哪個分頁（預設找「銷售紀錄」，找不到就用第一個分頁）。
   - `NAME_HEADERS`／`QTY_HEADERS`：你表格第一列的欄位標題。預設已涵蓋「商品名稱／品項／品名／商品」與「數量／售出數量／件數／銷量」，如果你的欄位叫別的名字，把它加進清單就好。
   - 如果表格**沒有數量欄**（一列就是賣出一件），不用改任何東西，腳本會自動每列算 1 件。
5. 按上方的儲存圖示（磁碟片）。

## 第一步半：在編輯器裡跑一次，完成授權（很重要）

1. 編輯器上方工具列有個函式下拉選單，選 **`testSalesApi`**，按 **執行（▶）**。
2. 第一次會跳出「需要授權」：
   - 點 **審查權限** → 選你的帳號
   - 出現「Google 尚未驗證這個應用程式」時點 **進階 → 前往（不安全的）專案** → **允許**
   （這是你自己寫給自己的程式，這個警告是正常的。）
3. 執行完成後，下方「執行紀錄」會直接印出統計 JSON，例如 `{"雙層緹花蛋糕裙":25,...}`。
   看到數字＝授權與讀表都成功，接著再去部署。

## 第二步：部署成網頁 API

1. 右上角點 **部署 → 新增部署作業**。
2. 左邊齒輪選 **網頁應用程式（Web App）**。
3. 三個欄位這樣填：
   - 說明：隨意，例如「官網熱銷排行統計」。
   - **執行身分：我（你的帳號）** ← 關鍵，這樣腳本才能用你的權限讀私密表。
   - **誰可以存取：所有人（Anyone）** ← 放心，這只開放「執行這支統計腳本」，
     任何人拿到網址也只看得到統計 JSON，完全碰不到試算表本身。
4. 按 **部署**。第一次會要求授權：選你的帳號 → 出現「Google 尚未驗證這個應用程式」時點
   **進階 → 前往（不安全）** →允許（這是你自己寫給自己的程式，這個警告是正常的）。
5. 部署完成後會給你一串 **網頁應用程式網址**，長得像：
   `https://script.google.com/macros/s/AKfycb.../exec`
   把它複製起來。

## 第三步：測試一下

把那串網址貼到瀏覽器打開，應該會看到類似這樣的純文字：

```json
{ "雙層緹花蛋糕裙": 25, "毛茸茸訂做兔耳帽": 18 }
```

- 看到統計數字＝成功。
- 看到錯誤訊息「找不到商品名稱欄」＝回第一步第 4 點，把你實際的欄位標題加進 `NAME_HEADERS`。

### 疑難排解

| 看到的錯誤 | 原因與解法 |
| --- | --- |
| 「指定的權限不足，無法呼叫 SpreadsheetApp.getActiveSpreadsheet」 | 舊版腳本用了「目前開啟的試算表」的讀法，網頁呼叫時抓不到。換成最新版腳本（改用 `SPREADSHEET_ID` 開啟）、填好 ID，先跑一次 `testSalesApi` 完成授權，再照下面「改完程式後怎麼重新發布」重新部署。 |
| 「請先在最上方的 SPREADSHEET_ID 填入試算表 ID」 | 回第一步第 4 點，把試算表網址 `/d/` 與 `/edit` 之間那串貼進去。 |
| 瀏覽器看到的還是舊錯誤 | 只按「儲存」不會更新已部署的網址，要照下面的方式「建立新版本」重新發布。 |

### 改完程式後怎麼重新發布（網址不變）

1. 右上角 **部署 → 管理部署作業**。
2. 點作用中那筆右邊的 **鉛筆（編輯）**。
3. 「版本」下拉選 **新版本（New version）**。
4. 按 **部署**。網址不會變，但內容從這一刻起才是新的程式碼與權限。

## 第四步：把網址接上官網

把第二步拿到的 `/exec` 網址交給 Claude（或自行填入
`src/app/core/brand.ts` 的 `SALES_API_URL` 常數），重新部署官網即可。

- 網址還沒填之前，官網一切照常，「熱銷排行」選項會暫時以上架新到舊呈現。
- 官網讀取失敗（斷網、腳本掛了）時銷量一律當 0，頁面不會壞。

## 日常維護

- **試算表照常記錄就好**，統計每 5 分鐘自動更新一次（`CACHE_SECONDS` 可調）。
- **改了 .gs 程式碼之後**要點 **部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選「新版本」→ 部署**，
  網址不變、內容才會更新（只按儲存不會生效）。
- **商品名稱要對得上**：官網是用「商品名稱」對照銷量的（會自動忽略空格與全半形差異）。
  試算表裡的品名請盡量與官網商品名稱一致；對不上的品項銷量會被當 0，不會報錯。
- 想作廢這支 API：部署 → 管理部署作業 → 封存即可，試算表不受任何影響。

## 安全備忘

- 試算表的共用設定從頭到尾都不用動（維持「僅限自己」）。
- 對外唯一的出口是這支腳本，而它只輸出名稱＋數量；就算網址流出，
  別人也只看得到「哪件娃衣賣得好」，看不到任何客人資料或金額。
- 想再保險一點，可以不定期「封存舊部署、重新部署」換一個新網址（記得同步更新官網常數）。
